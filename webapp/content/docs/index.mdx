# FluxMedia

**Unified media uploads for JavaScript**

FluxMedia is a unified API for uploading images, videos, and files to any cloud storage provider. Write your upload logic once, and it works with every provider.

## Features

- **Unified API** - Use Cloudinary, S3, R2, Google Cloud Storage, Azure Blob Storage or the local filesystem with one interface
- **Secure browser uploads** - Server handlers that authenticate, check type (by content) and size, and choose the folder on the server; signed upload URLs that enforce type and size on S3/R2
- **Private files** - Optional public URLs and time-limited signed download URLs on every provider
- **File operations** - Get, delete (batched), list with cursors, copy, move, download streams, metadata updates
- **Streaming Support** - Upload from File, Buffer, Readable, or ReadableStream, with byte progress and cancel
- **Fallback Providers** - Automatic failover when the primary provider fails
- **Transactional Uploads** - Upload-then-commit with rollback
- **React Hooks** - `useMediaUpload`, `useMediaUploadQueue` and a drag-and-drop component
- **Plugin System** - Validation, optimization, virus scanning, dedupe, placeholders, retry, analytics, or your own
- **Structured Errors** - Typed error codes (`ABORTED`, `NOT_SUPPORTED`, `RATE_LIMITED`, …)
- **Tree-shakeable** - SDKs are peer dependencies and load lazily

## Quick Start

```bash npm2yarn
npm install @fluxmedia/core @fluxmedia/cloudinary
```

```typescript
import { MediaUploader } from '@fluxmedia/core';
import { CloudinaryProvider } from '@fluxmedia/cloudinary';

const uploader = new MediaUploader(
  new CloudinaryProvider({
    cloudName: 'your-cloud',
    apiKey: 'your-key',
    apiSecret: 'your-secret',
  })
);

const result = await uploader.upload(file, {
  folder: 'uploads',
  transformation: { width: 800, format: 'webp' },
});

console.log(result.url);
console.log(result.storageKey); // Provider-specific storage key
```

## Packages

| Package | Description |
|---------|-------------|
| `@fluxmedia/core` | MediaUploader, plugin system, server upload handlers (`@fluxmedia/core/server`), in-memory provider, signed-URL helpers, file type detection |
| `@fluxmedia/cloudinary` | Cloudinary provider with transformations |
| `@fluxmedia/s3` | AWS S3 and S3-compatible storage (MinIO, B2, Wasabi, Spaces, Supabase) |
| `@fluxmedia/r2` | Cloudflare R2 (S3 API, or Workers bucket bindings) |
| `@fluxmedia/gcs` | Google Cloud Storage |
| `@fluxmedia/azure` | Azure Blob Storage |
| `@fluxmedia/local` | Local filesystem |
| `@fluxmedia/react` | React hooks and components |
| `@fluxmedia/plugins` | Official plugins: validation, optimization, metadata, virus scanning, dedupe, placeholders, analytics, retry |

## Why FluxMedia?

### Before FluxMedia

```typescript
// Cloudinary SDK
import cloudinary from 'cloudinary';
cloudinary.v2.uploader.upload(file, { folder: 'uploads' });

// S3 SDK — completely different API
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
// ... lots of boilerplate
```

### With FluxMedia

```typescript
// Unified interface
import { MediaUploader } from '@fluxmedia/core';
import { CloudinaryProvider } from '@fluxmedia/cloudinary';
// OR
import { S3Provider } from '@fluxmedia/s3';

// Same API, consistent behavior
const uploader = new MediaUploader(new CloudinaryProvider({ ... }));
// OR
const uploader = new MediaUploader(new S3Provider({ ... }));

// With fallback provider for resilience
const uploader = new MediaUploader(
  new CloudinaryProvider({ ... }),
  [],
  { fallbackProvider: new S3Provider({ ... }) }
);
```
